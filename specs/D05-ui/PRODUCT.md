## Summary

本切片修的是同一类缺陷：**界面显示的东西，不是应用真正持有或真正会做的东西**。URL 栏显示一串用户没打过、也不会发出去的百分号编码；环境变量的输入框在你打第二个字符时被销毁；一条已解析失败的粘贴凭空消失；两个折叠开关共用一个状态；一个 warning 数组被生产出来却没人渲染。这些全部踩在项目最高红线「UI 不许说谎」上，也正因如此，本切片把「一个看起来能用、实际什么都不做的控件」按 HIGH 处理，而不是按 nit。

同时交付导入导出切片留下的三项发布阻断交接与它未落地的 7 个 i18n key（裁定 A16）。

## Problem

八条 backlog 缺陷 + 三项交接，按机制归成六组：

- **URL 栏是个谎言机器**。`buildUrlWithParams` 用 `URLSearchParams` 重建展示串，`{{apiKey}}` 变成 `%7B%7BapiKey%7D%7D`，于是「包含变量」提示对查询串里的变量永远不出现（它对路径里的变量却出现——不一致比全无更糟）。同一次往返还吃掉逐字符键入的 `?`：手打 `https://api.test/a?x=1` 得到 `https://api.test/ax=1`，**查询串在这个应用里根本打不进去**。
- **环境变量行用自身内容当身份**。敲一个字符，`:key` 变了，Vue 卸载重建输入框，焦点掉到 `<body>`。建一个 8 字符的变量名要点 8 次。键值编辑器早就用持久化的 `id` 解决了同一问题，环境面板是唯一的例外。
- **在途请求没有闸门**。回车不判 `isLoading`，两次回车发两个真请求；先到的那个响应、控制台完成行、历史条目全部被静默丢弃。按住回车会发几十个。按钮防住了，键盘没有。
- **两处身份键取错了**。历史分组用展示文案当 key，`{{baseUrl}}/users` 与 `{{baseUrl}}/orders` 得到两个分组、同一个文案，折叠一个另一个跟着折叠；`openHistoryEntry` 的复用判定不看项目绑定，于是从集合打开的 tab 被历史条目劫持，`savedRequestPath` 丢失，再点集合里的同一条会开出第二个 tab。
- **导入的失败与降级全部无声**。粘贴 `curl -H 'Accept: application/json'`（无 URL）→ `preventDefault()` 已经执行 → 解析抛错 → 空 catch → 剪贴板内容凭空消失。导入成功时 `parseCurl` 返回的 `warnings` 没有任何渲染点：`-b cookies.txt` 会**删掉一个 Cookie**，只留下一条没人读的 warning。
- **导出告警从未接上**。`collectPostmanExportWarnings` 被导出、被测试，全仓零调用点。

> **rev1 在这里写过的第七组（导出判据 `!== undefined` 恒真）已经作废。** 该缺陷已由导入导出切片在 main 上修复：判据改为 `typeof fileContent === "string"`，并补了 `null` 形状的 fixture 与 P6 式自检。**本切片不再重写该判据**——rev1 的写法会把刚修掉的那句假话原样重新制造出来，并推翻已冻结的回归测试。相关的产品层疑问改以受控裁定申请的形式单独提出，见 TECH §6。

## 本切片的判定线

**一个控件看起来能用而实际什么都不做，或者一个显示出来的值与真正被使用的值不同，在这里是 HIGH，不是 nit。** 三条推论，下面每一条不变式都受其约束：

1. 不许用「改文案」来消化一个做不到的能力——只有补实现或删入口。
2. 一条**永远为真**的告警和一条**永远不出现**的告警一样有害：前者是墙纸，后者是哑控件。因此每一条告警都必须有「它什么时候不出现」的负向不变式。
3. 展示值与生效值只允许在**已声明的两处**分叉：URL 栏展示的是变量解析**之前**的请求（§2 的适用面）；认证层追加的 query API key 不在 URL 栏出现（§4）。除此之外逐字节一致。

## 告警呈现机制（设计裁定，非菜单）

现有三个告警生产者：历史脱敏切片的「待重填」提示条（请求面板顶部，常驻），导入 warning，导出 warning。**不做三套机制，也不合成一套**——按一条判据分成两类：

> **告警描述的条件此刻仍然为真、且能从当前状态重新推导出来 ⇒ 常驻提示条（不可关闭，条件消失即自动消失）。**
> **告警描述的是一次已经完成的动作 ⇒ 动作结果通知（可关闭，被同类动作的下一次结果取代，永不阻断）。**

- 「待重填」提示条属第一类：条件可从 tab 状态重新推导，关闭它就会制造「值是空的、提示没了」的说谎状态。**本切片不动它。**
- 导入 warning 属第二类。它挂在 **tab** 上（内存态字段，与「待重填」标记同款），因为它描述的是这个 tab 里发生过的一次导入；切走再切回仍在，直到用户按 ✕ 或对同一 tab 再导入一次。**为什么不能随切 tab 消失**：`data-segments-discarded` / `cookie-file-not-supported` / `authorization-not-byte-preserved` 三种降级在 UI 上**无法从当前状态重新推导**（原始 curl 文本已经不存在），通知一旦消失，损失就永远不可见了。
- 导出 warning 也属第二类，但它的作用对象是**项目**不是 tab，所以复用集合面板已有的 feedback 条（现有 `success` / `error` 两种 tone，增加 `warning`），而不是新造一个第三处。

结果是：**两类机制、三个渲染点，每个渲染点都是它所在面板本来就有的那一个。**

## Behavior

### A. URL 栏与查询串

1. URL 栏渲染的查询串里，`{{…}}` 模板整段原样显示——键和值都是，一个 URL 里出现多个模板、模板与普通文本混排（`x{{a}}y`）、模板内部带空格（`{{ a }}`）都一样。
2. **由启用的 Params 行生成的那一段查询串**，模板跨度之外的每个字节与后端对**同一批 Params 行**的编码逐字节一致：空格是 `+` 不是 `%20`，`!` `~` `(` `)` `'` 按百分号编码，`&` `=` 在键值内部被转义，非 ASCII 按 UTF-8 百分号编码，重复键各自出现，被禁用的行不出现。参与生成的过滤条件与后端相同：`enabled` 为真**且 `key` 去除首尾空白后非空**。
3. `key` 为纯空白的参数行**既不出现在 URL 栏、也不会被发送**——两侧一致地忽略它。（现状是它会显示但不会发送。）
4. **认证层追加的 query API key 不在 URL 栏出现**（负向不变式）。后端在追加完 Params 之后还会追加 `auth.type === "api-key" && addTo === "query"` 的那一对；URL 栏不复现它——那个值通常就是密钥，把它渲染进地址栏是主动泄露。§2 的一致性承诺因此**只覆盖 Params 行生成的那一段**，这条边界必须显式成立，不能默认成立。
5. 「包含变量」提示同时覆盖路径中的变量与查询串中的变量，去重后按出现顺序列出；被禁用的参数里的变量不计入。
6. **逐字符键入任意 URL，输入框显示的始终恰好是已键入的那串字符**——包括刚打完 `?` 的那一刻、只打到 `?x` 还没打 `=` 的那一刻、含空格的值、含 `#` 片段、重复键、以及用户自己写的百分号编码（`%E4%B8%AD` 不被解码成 `中`）。
7. 粘贴一段普通 URL（不以 `curl ` 开头），输入框内容与剪贴板逐字节相同。
8. 当 URL 的变化**来自输入框之外**——Params 表编辑、cURL 导入、从历史或集合打开、方法切换引发的重渲染——输入框改为显示新状态的规范形式，不保留旧草稿。
9. 切换 tab 后，输入框绝不显示另一个 tab 遗留的草稿；即使两个 tab 的 URL 恰好解析结果相同也不复用。

### B. 在途请求

10. 同一个 tab 已有在途请求时，再次发起发送**不产生第二次后端调用**。对所有发送入口一视同仁——URL 栏回车、Cmd/Ctrl+Enter、Send 按钮，以及将来新增的任何入口。
11. 该拒绝发生在**为新请求铸造追踪 id 之前**：在途请求自己的响应、历史条目一条都不丢。（闸门放在铸造之后同样能挡住第二次后端调用，却已经把在途请求的账毁了——两件事必须分别成立、分别被证明。）
12. 在途请求以任何方式结束（成功、失败、取消完成）之后，同一个 tab 可以立即再次发送——闸门不是单向的。
13. 在途期间在 URL 栏按回车没有任何效果：既不发送，也不取消（取消由按钮承担，按钮在途时已经是 Cancel）。按住回车触发的自动重复同样无效。

### C. 环境变量行

14. 行身份与行内容无关：编辑键、编辑值、切换 secret 都不改变该行身份。连续键入 N 个字符后，该行的键恰好是这 N 个字符（不是第 1 个）。
15. 删除某一行只删该行，无论它的键与其他行是否重名、是否为空。
16. 列表末尾始终恰好有一个空白行；在空白行里填入任何内容后，其后自动追加新的空白行；把某行清空不会产生第二个空白行。
17. 变量被**从外部整体替换**时（切换环境、重新加载环境、请求前脚本写入变量），行模型重新播种，面板显示新数据。
18. 行的 UI 身份是纯内存态：既不写进 `.env.json`，也不出现在任何持久化负载里。

### D. 历史分组

19. 每个分组带一个与展示文案无关的稳定唯一标识；`new URL()` 解析不了 host 时（`{{baseUrl}}/users` 与 `{{baseUrl}}/orders`）两个分组的标识仍然不同，即使两者展示文案完全相同。三种分组模式（prefix / time / method）都成立。
20. 折叠状态按分组标识记录：折叠一个分组不影响任何其他分组，包括展示文案与它相同的那个。
21. 分组列表的渲染身份也用该标识，不用展示文案。

### E. 从历史打开请求

22. 绑定到集合的 tab（有项目名或有已保存路径）**永远不会**被历史条目复用——历史条目另开新 tab。
23. 没有绑定的空白 tab 仍按**完整请求身份**复用（protocol / method / url / params / headers / body / auth / scripts 全等且尚无响应），不得退化成按 method+url 去重。

### F. cURL 导入的查询串

24. cURL 导入之后（对话框路径与粘贴路径都一样），`tab.url` 不含查询串，查询参数只存在于 params——与手打 URL 后的状态完全相同。用户不做任何编辑也成立。
25. 导入之后不做任何编辑直接 Copy as cURL，每个查询参数只出现一次。
26. 导入之后不做任何编辑直接导出 Postman 集合，每个查询参数在 `url.raw` 里只出现一次。

### G. 粘贴 cURL

27. 粘贴一段以 `curl ` 开头但**解析失败**的文本（无 URL 的片段、大写 `Curl …`）时，判定结果是「按普通文本插入」，因此浏览器的默认粘贴行为不被取消。**绝不允许出现「粘贴了但什么都没有发生」。**
28. 该判定同时携带解析失败的原因。
29. **请求面板真的把这个原因渲染出来**——判定正确但没人渲染，与什么都不做等价。
30. 可以解析的 cURL 粘贴仍然按导入处理：方法、URL、请求头、body、认证被写入 tab，原始 cURL 文本**不**落进 URL 栏。

### H. 导入告警

31. `parseCurl` 报出的每一个 warning code 都被映射成一条可读、已本地化、带具体细节（文件名 / 段数 / cookie 文件名 / 「换行」等）的文案。新增 warning 类型时，漏掉文案必须在构建期被发现，而不是在界面上显示成一个代号。
32. **请求面板真的把这些文案渲染成同样条数的行**——`parseCurl` 报 3 条，界面上就是 3 行。
33. 对同一个 tab 再导入一次时，告警被新结果**整体取代**；新结果没有 warning 就是清空。（告警挂在 tab 上，因此切走再切回仍在。）
34. 用户可以显式关闭告警条，关闭只作用于当前 tab。
35. 导入告警不阻断任何操作：带着告警仍然可以发送、可以保存、可以再次导入。
36. 导入告警不写进历史条目。
37. 导入告警不写进已保存请求。

### I. 导出告警

38. **导出 Postman 集合时那条链路真的被接上**：集合面板在导出后调用告警收集，并把结果交给它自己那条 feedback 显示。（今天它一次都没被调用过。）
39. 没有告警时，导出只报成功，色调是成功色，不出现告警次行。
40. 有告警时，**导出成功这一事实仍然被报告**，色调改为告警色，次行给出涉及的数量——告警是对成功导出的补充说明，不是失败。

> **已知且已入账的边界**：按 main 现状的判据（内容字段是字符串才算「我们持有字节」），集合导出走的 `loadRequest` 链路拿到的永远是 `null`，因此**这条告警在今天的集合导出路径上不会触发**。§38 锁的是「链路接上了」，§39 锁的是「不触发时不说谎」，§40 锁的是「触发时不被误报成失败」。至于「文件行本身是否值得提示用户在 Postman 里重选」，是一个**产品问题**而不是缺陷，作为受控裁定申请单独提出（TECH §6），不在本切片的不变式内。

### J. 调试控制台

41. 应用能产生的每一个日志级别都有对应的过滤选项。今天 `info` 是应用几乎唯一实际写入的级别，却没有选项；修好之后，新增级别而漏加选项必须在构建期被发现。
42. 过滤选项的全部文案走 i18n，中文界面不出现 `Log` / `Warn` / `Error` 三个英文按钮夹在「全部」旁边。
43. **控制台面板真的把这些选项渲染成按钮**——选项列表正确但没渲染，与没有选项等价。
44. 同一批硬编码英文文案一并本地化：cURL 导入对话框的示例（locale 里 `request.curlExample` 早就定义了却从未被使用），以及 form-data 的 `Type` 列头与 `Text` / `File` 两个选项。

### K. 控制台 store

45. 记录一条控制台条目不改变调用方的 pinia 绑定——调用之后 `getActivePinia()` 仍是调用前那一个。
46. 条目不写进模块单例。

### L. 文案

47. 导入导出切片定义但**没有落地**的 7 个 key（裁定 A16）在两个 locale 中都存在，文案与该切片交接清单约定的一致，且各自保留其插值占位符（`{method}` / `{count}` / `{detail}`）。
48. cURL 导入对话框的说明文字与解析器**实际支持**的 flag 一致。
49. 两个 locale 的键集完全一致（既有不变式，本切片扩容后仍成立）。

导入告警条位于请求面板顶部、「待重填」提示条**之下**，同为一行式条带，用中性/琥珀色区分「结果通知」与「当前状态」；右端一个 ✕。集合面板 feedback 条增加 `warning` 色调（琥珀），主行是导出成功，次行是告警。全部沿用既定 token：控件 4px 圆角、容器 8px、基础字号 14px、1024×768 不换行。

## Non-goals

- **不重写导出告警的判据**。它已在 main 上被另一切片按真实 IPC 形状修好并加了回归测试；本切片只接线。
- **不动「待重填」提示条的行为**——另一个切片的既定决策。
- **组件测试的适用面被硬性限定**。引入 `@vue/test-utils` 之后，组件测试**只允许**断言四类事实：(1) 组件发出的事件；(2) 传给子组件的 props；(3) `v-if` / `v-for` 的存在性与条数；(4) 对 store 或注入函数的调用。**明确禁止**断言焦点、选区、光标位置、布局、`document.activeElement`、以及任何依赖真实排版的东西——那些在 DOM 模拟环境里与 WebKit 行为不同，绿灯会是假的。这条边界不是风格偏好，是本次引入的前提条件；越界的断言按缺陷处理。
- 历史条目的单条删除入口（裁定 A17 归 D07a）。
- 不改后端（`src-tauri/**` 一个字不动）。
- 不改 WebSocket 相关的 tab 生命周期。
- 不改 `KeyValueEditor.vue`。
- 不修后端零参数时 URL 仍带尾随 `?`。
- **不做焦点恢复机制**。§14 修的是「行身份不再变化」，因此输入框根本不被卸载。
