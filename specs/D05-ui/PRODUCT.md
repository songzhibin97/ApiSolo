## Summary

本切片修的是同一类缺陷：**界面显示的东西，不是应用真正持有或真正会做的东西**。URL 栏显示一串用户没打过、也不会发出去的百分号编码；环境变量的输入框在你打第二个字符时被销毁；一条已解析失败的粘贴凭空消失；两个折叠开关共用一个状态；一个 warning 数组被生产出来却没人渲染。这些全部踩在项目最高红线「UI 不许说谎」上，也正因如此，本切片把「一个看起来能用、实际什么都不做的控件」按 HIGH 处理，而不是按 nit。

同时交付导入导出切片留下的三项发布阻断交接与它未落地的 7 个 i18n key（裁定 A16）。

## Problem

八条 backlog 缺陷 + 三项交接，按机制归成六组：

- **URL 栏是个谎言机器**。`buildUrlWithParams` 用 `URLSearchParams` 重建展示串，`{{apiKey}}` 变成 `%7B%7BapiKey%7D%7D`，于是「包含变量」提示对查询串里的变量永远不出现（它对路径里的变量却出现——不一致比全无更糟）。同一次往返还吃掉逐字符键入的 `?`：手打 `https://api.test/a?x=1` 得到 `https://api.test/ax=1`，**查询串在这个应用里根本打不进去**。
- **环境变量行用自身内容当身份**。敲一个字符，`:key` 变了，Vue 卸载重建输入框，焦点掉到 `<body>`。建一个 8 字符的变量名要点 8 次。键值编辑器早就用持久化的 `id` 解决了同一问题，环境面板是唯一的例外。
- **在途请求没有闸门**。回车不判 `isLoading`，两次回车发两个真请求；先到的那个响应、控制台完成行、历史条目全部被静默丢弃。按住回车会发几十个。按钮防住了，键盘没有。
- **两处身份键取错了**。历史分组用展示文案当 key，`{{baseUrl}}/users` 与 `{{baseUrl}}/orders` 得到两个分组、同一个文案，折叠一个另一个跟着折叠；`openHistoryEntry` 的复用判定不看项目绑定，于是从集合打开的 tab 被历史条目劫持，`savedRequestPath` 丢失，再点集合里的同一条会开出第二个 tab。
- **导入的失败与降级全部无声**。粘贴 `curl -H 'Accept: application/json'`（无 URL）→ `preventDefault()` 已经执行 → 解析抛错 → 空 catch → 剪贴板内容凭空消失。导入成功时 `parseCurl` 返回的 `warnings` 没有任何渲染点：`-b cookies.txt` 会**删掉一个 Cookie**，只留下一条没人读的 warning。
- **导出告警从未接上**。`collectPostmanExportWarnings` 被导出、被测试，全仓零调用点。

> **rev1 在这里写过的第七组（导出判据 `!== undefined` 恒真）已经作废。** 该缺陷已由导入导出切片在 main 上修复：判据改为 `typeof fileContent === "string"`，并补了 `null` 形状的 fixture 与 P6 式自检。**本切片不再重写该判据**——rev1 的写法会把刚修掉的那句假话原样重新制造出来，并推翻已冻结的回归测试。相关的产品层疑问改以受控裁定申请的形式单独提出，见 TECH §6。

## 本切片的判定线

**一个控件看起来能用而实际什么都不做，或者一个显示出来的值与真正被使用的值不同，在这里是 HIGH，不是 nit。** 三条推论，下面每一条不变式都受其约束：

1. 不许用「改文案」来消化一个做不到的能力——只有补实现或删入口。
2. 一条**永远为真**的告警和一条**永远不出现**的告警一样有害：前者是墙纸，后者是哑控件。因此每一条告警都必须有「它什么时候不出现」的负向不变式。
3. 展示值与生效值只允许在**已声明的两处**分叉：URL 栏展示的是变量解析**之前**的请求（§2 的适用面）；认证层追加的 query API key 不在 URL 栏出现（§4）。除此之外逐字节一致。

## 告警呈现机制（设计裁定，非菜单）

现有三个告警生产者：历史脱敏切片的「待重填」提示条（请求面板顶部，常驻），导入 warning，导出 warning。**不做三套机制，也不合成一套**——按一条判据分成两类：

> **告警描述的条件此刻仍然为真、且能从当前状态重新推导出来 ⇒ 常驻提示条（不可关闭，条件消失即自动消失）。**
> **告警描述的是一次已经完成的动作 ⇒ 动作结果通知（可关闭，被同类动作的下一次结果取代，永不阻断）。**

- 「待重填」提示条属第一类：条件可从 tab 状态重新推导，关闭它就会制造「值是空的、提示没了」的说谎状态。**本切片不动它。**
- 导入 warning 属第二类。它挂在 **tab** 上（内存态字段，与「待重填」标记同款），因为它描述的是这个 tab 里发生过的一次导入；切走再切回仍在，直到用户按 ✕ 或对同一 tab 再导入一次。**为什么不能随切 tab 消失**：`data-segments-discarded` / `cookie-file-not-supported` / `authorization-not-byte-preserved` 三种降级在 UI 上**无法从当前状态重新推导**（原始 curl 文本已经不存在），通知一旦消失，损失就永远不可见了。
- 导出 warning 也属第二类，但它的作用对象是**项目**不是 tab，所以复用集合面板已有的 feedback 条（现有 `success` / `error` 两种 tone，增加 `warning`），而不是新造一个第三处。

结果是：**两类机制、三个渲染点，每个渲染点都是它所在面板本来就有的那一个。**

## Behavior

### A. URL 栏与查询串

1. URL 栏渲染的查询串里，`{{…}}` 模板整段原样显示——键和值都是，多个模板、模板与普通文本混排（`x{{a}}y`）、模板内部带空格（`{{ a }}`）都一样。
2. **由启用的 Params 行生成的那一段查询串**，模板跨度之外的每个字节与后端对**同一批 Params 行**的编码逐字节一致：空格是 `+` 不是 `%20`，`!` `~` `(` `)` `'` 按百分号编码，`&` `=` 在键值内部被转义，非 ASCII 按 UTF-8 百分号编码，重复键各自出现，被禁用的行不出现。过滤条件与后端相同：`enabled` 为真**且 `key` 去除首尾空白后非空**。
3. `key` 为纯空白的参数行**既不出现在 URL 栏、也不会被发送**——两侧一致地忽略它。
4. **认证层追加的 query API key 不在 URL 栏出现**（负向不变式）。后端在追加完 Params 之后还会追加 `auth.type === "api-key" && addTo === "query"` 的那一对；URL 栏不复现它——那个值通常就是密钥。§2 的一致性承诺因此**只覆盖 Params 行生成的那一段**。
5. **该分叉写进两个 README**：明确说明 query API key 只在发送时追加、出于密钥保护不显示在 URL 栏。（项目硬规则：决策不落到 README，下一轮扫描会当高危 bug 重报，或者有人「顺手」把密钥拼回地址栏。）
6. **该分叉在 UI 上就地说明**：认证面板选择「添加到 Query」时，同处给出一句解释，让用户能区分「安全设计」与「功能失效」。现状只写「添加到 Query」，用户看不到参数时无从判断。
7. 「包含变量」提示同时覆盖路径与查询串中的变量，去重后按出现顺序列出；被禁用的参数里的变量不计入。
8. **逐字符键入任意 URL，输入框显示的始终恰好是已键入的那串字符**——包括刚打完 `?` 的那一刻、只打到 `?x` 的那一刻、含空格的值、含 `#` 片段、重复键、以及用户自己写的百分号编码（`%E4%B8%AD` 不被解码成 `中`）。
9. 粘贴一段普通 URL（不以 `curl ` 开头），输入框内容与剪贴板逐字节相同。
10. 当 URL 的变化**来自输入框之外**——Params 表编辑、cURL 导入、从历史或集合打开——输入框改为显示新状态的规范形式，不保留旧草稿。（**方法切换不在此列**：它不改变 URL，草稿理应原样留着；把它算作外部写入会无故清掉用户正在编辑的地址。）
11. **即使外部写入的结果与当前草稿「解析后等价」，也必须采纳外部值**。例：草稿 `https://x/a?q=a%20b`，一次 cURL 导入把状态改成规范形式 `https://x/a?q=a+b`——解析结果相同但状态已变，界面必须跟着变。判据只能是「这次变化是不是我自己引起的」，**不能**是「新旧值语义是否相同」。
12. **外部写入即使让渲染出的 URL 字符串一字不变，界面也必须重新协调**。例：草稿 `%20` 已 self-echo 成规范的 `+`，随后一次 cURL 导入写入同样的 `+` 而只改变来源标记——此时 URL 字符串没变，但界面上仍挂着用户那份 `%20` 草稿，必须被换掉。**这一条约束的是「协调逻辑有没有被执行」，不是「协调逻辑算得对不对」**——后者由 §11 覆盖，两者是两层。
13. 切换 tab 后，输入框绝不显示另一个 tab 遗留的草稿；即使两个 tab 的 URL 恰好解析结果相同也不复用。

### B. 在途请求

14. 同一个 tab 已有在途请求时，再次发起发送**不产生第二次后端调用**。对所有发送入口一视同仁——URL 栏回车、Cmd/Ctrl+Enter、Send 按钮，以及将来新增的任何入口。
15. 被拒绝的那次发送**不得扰动在途请求的记账**：在途请求自己的响应仍然落到 tab 上，历史仍然被追加恰好一次。（只挡住第二次调用是不够的——一个「早退但顺手改了追踪表」的实现同样只发一次请求，却会把第一次的结果整个丢掉。）
16. 在途请求以任何方式结束（成功、失败、取消完成）之后，同一个 tab 可以立即再次发送。
17. 在途期间在 URL 栏按回车没有任何效果：既不发送，也不取消。按住回车触发的自动重复同样无效。

### C. 环境变量行

18. 行身份与行内容无关：编辑键、编辑值、切换 secret 都不改变该行身份。连续键入 N 个字符后，该行的键恰好是这 N 个字符。
19. 删除某一行只删该行，无论它的键与其他行是否重名、是否为空。
20. 列表末尾始终恰好有一个空白行；填入内容后自动追加新的空白行；把某行清空不会产生第二个空白行。
21. 变量被**从外部整体替换**时（切换环境、重新加载、请求前脚本写入），行模型重新播种。
22. 行的 UI 身份是纯内存态：既不写进 `.env.json`，也不出现在任何持久化负载里。

### D. 历史分组

23. 每个分组带一个与展示文案无关的稳定唯一标识；`new URL()` 解析不了 host 时两个分组的标识仍然不同，即使展示文案完全相同。三种分组模式都成立。
24. 折叠状态按分组标识记录：折叠一个分组不影响任何其他分组，包括展示文案与它相同的那个。
25. 分组列表的渲染身份也用该标识，不用展示文案。

### E. 从历史打开请求

26. 绑定到集合的 tab **永远不会**被历史条目复用——历史条目另开新 tab。
27. 没有绑定的空白 tab 仍按**完整请求身份**复用，不得退化成按 method+url 去重。

### F. cURL 导入的查询串

28. cURL 导入之后（两条路径都一样），`tab.url` 不含查询串，查询参数只存在于 params。
29. 导入后不做任何编辑直接 Copy as cURL，每个查询参数只出现一次。
30. 导入后不做任何编辑直接导出 Postman 集合，每个查询参数在 `url.raw` 里只出现一次。

### G. 粘贴 cURL

31. 粘贴一段以 `curl ` 开头但**解析失败**的文本时，判定结果是「按普通文本插入」，默认粘贴行为不被取消。**绝不允许「粘贴了但什么都没有发生」。**
32. 该判定同时携带解析失败的原因。
33. **解析失败的三种原因全部本地化**：不是 cURL 命令、命令里找不到 URL、方法不受支持。
34. **请求面板真的把这个原因交给翻译并渲染出来**——判定正确但没人渲染，与什么都不做等价。
35. 可以解析的 cURL 粘贴仍然按导入处理，原始 cURL 文本**不**落进 URL 栏。

### H. 导入告警

36. `parseCurl` 报出的每一个 warning code 都被映射成一条可读、已本地化的文案。新增 warning 类型时，漏掉文案必须在构建期被发现。
37. **warning 的 detail 永远是数据，不是散文**（负向不变式）。文件名、段数、cookie 文件名是数据，可以插进任一语言的句子；`"line breaks"` 这类英文短语不是。凡是要区分「哪种情况」的一律拆成独立 code，各配完整文案，**detail 不承载散文**。
38. **请求面板真的把这些文案渲染成同样条数的行**——报 3 条就是 3 行。
39. 对同一个 tab 再导入一次时，告警被新结果**整体取代**；新结果没有 warning 就是清空。
40. 用户可以显式关闭告警条，关闭只作用于当前 tab。
41. 导入告警不阻断任何操作。
42. 导入告警不写进历史条目。
43. 导入告警不写进已保存请求。

### I. 导出告警

44. **导出 Postman 集合时那条链路真的被接上**：集合面板在导出后调用告警收集，并把结果交给它自己那条 feedback。
45. 没有告警时，**不出现告警次行**。
46. 没有告警时，色调是成功色。
47. 有告警时，**导出成功这一事实仍然被报告**。
48. 有告警时，色调改为告警色。
49. 有告警时，次行给出的数量与实际告警条数一致。

> **已知且已入账的边界**：按 main 现状的判据（内容字段是字符串才算「我们持有字节」），集合导出走的 `loadRequest` 链路拿到的永远是 `null`，因此**这条告警在今天的集合导出路径上不会触发**。§44 锁「链路接上了」，§45/§46 锁「不触发时不说谎」，§47–§49 锁「触发时不被误报成失败、且数字属实」。「文件行本身是否值得提示重选」是产品问题，已单列 backlog 条目。

### J. 调试控制台

50. 应用能产生的每一个日志级别都有对应的过滤选项；新增级别而漏加选项必须在构建期被发现。
51. 过滤选项的全部文案走 i18n。
52. **控制台面板真的把这些选项渲染成按钮**。
53. 同一批硬编码英文文案一并本地化：cURL 导入对话框的示例、form-data 的 `Type` 列头与 `Text` / `File` 选项。

### K. 控制台 store

54. 记录一条控制台条目不改变调用方的 pinia 绑定。
55. 条目不写进模块单例。

### L. 文案

56. **本切片经手的每一个 key，两种语言的文案都与规格表逐字一致**（14 个自有 + 6 个继承）。仅断言「key 能解析出非 key 本身的字符串」是不够的——把 zh-CN 文案整条写成英文照样能通过；仅断言「占位符还在」也不够——把文案换成任意错误句子照样能通过。
57. cURL 导入对话框的说明文字与解析器**实际支持**的 flag 一致。
58. 两个 locale 的键集完全一致。

## Non-goals

- **不重写导出告警的判据**。它已在 main 上被另一切片按真实 IPC 形状修好并加了回归测试；本切片只接线。
- **不动「待重填」提示条的行为**——另一个切片的既定决策。
- **组件测试的适用面被硬性限定（裁定 A20）**。组件测试**只允许**断言四类事实：(1) 组件发出的事件；(2) 传给子组件的 props；(3) `v-if` / `v-for` 的存在性与条数；(4) 对 store 或注入函数的调用。**明确禁止**断言焦点、选区、光标位置、布局、`document.activeElement`、DOM 文本内容，以及任何依赖真实排版的东西——那些在 DOM 模拟环境里与 WebKit 行为不同，绿灯会是假的。这条边界不是风格偏好，是本次引入的前提条件；越界的断言按缺陷处理。
  > rev3 自己越过了一次：把「通知条内出现原因文本」写成承重断言，那是 DOM 文本断言，不在获准的四类里。rev4 已改回（§34）。**自己划的边界自己越界**，与「用一条正确的原则为一个错误的结论辩护」同源，所以把这次越界留在这里。
- 历史条目的单条删除入口（裁定 A17 归 D07a）。
- 不改后端（`src-tauri/**` 一个字不动）。
- 不改 WebSocket 相关的 tab 生命周期。
- 不改 `KeyValueEditor.vue`。
- 不修后端零参数时 URL 仍带尾随 `?`。
- **不做焦点恢复机制**。§18 修的是「行身份不再变化」，因此输入框根本不被卸载。
